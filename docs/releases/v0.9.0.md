# Core v0.9.0 — Checkout Fiscalization Choice

Релиз уточняет кассовый checkout: способ фискализации теперь определяется выбранным оператором
вариантом оплаты для конкретной продажи, без глобального выключателя фискализации.

## Возможности

- ровно три операторских сценария: «Карта / QR», «Наличными + чек» и «Наличными без чека»;
- явное подтверждение получения наличных перед фиксацией успешной оплаты;
- наличные никогда не запускают acquiring;
- «Наличными + чек» формирует фискальный чек через настроенный AQSI FiscalProvider;
- «Наличными без чека» не вызывает AQSI и сохраняет отдельный статус `SKIPPED`;
- Card/QR всегда требует фискализацию и не имеет варианта без чека;
- Inventory `SALE` movements создаются ровно один раз для Catalog-позиций;
- Manual SaleItems остаются продажами без складских движений;
- история продажи различает оплату наличными и намеренно не сформированный чек.

## Интерфейс

- сумма к получению показывается перед подтверждением наличной оплаты;
- кнопка «Получено наличными» является явным платёжным действием;
- варианты оплаты и блок фискальной кассы адаптированы для узких экранов;
- радиокнопки имеют фиксированный размер, а подписи выровнены по левому краю;
- cache-key статических ресурсов обновлён для корректного обновления Safari.

## Архитектура

- `PaymentAttempt.fiscalization_required` сохраняет принятое checkout-решение;
- `Fiscalization.SKIPPED` является самостоятельным durable fact, а не `SUCCESS`, `FAILED` или
  `UNKNOWN`;
- для `SKIPPED` отсутствуют provider и Integration;
- payment, Inventory posting и fiscalization остаются отдельными идемпотентными фактами.

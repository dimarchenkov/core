# Неактуальная операция №92

21.10.2026 оператор явно попросил отметить операцию на 50 ₽ как неактуальную
и не выполнять с ней дальнейших действий. Цель определена по платёжному ID со скриншота:
это Sale №92, а не зависшая операция Sale №109.

Отметка применена к рабочей базе 21.10.2026 в 20:04 МСК. Перед изменением создан
и полностью проверен `backups/reconciliation-2026-10-20/before-dismiss-sale92-20261021.dump`
(SHA-256 `7220c24e247ac6e8ae01ca7c391231a57337802c453f0465e3ebec3a5e313bdc`).
Сравнение исходных и итоговых записей подтвердило неизменность Sale, PaymentAttempt,
StockMovement, суммы/статуса/внешних ID фискального факта.
API и worker пересобраны; миграции не требуются. Коммитов не было.

## Семантика отметки

`Fiscalization.provider_metadata.operator_dismissed=true` — только решение о дальнейшей
операционной обработке. Это не возврат, не отмена оплаты и не подтверждение наличия чека.
В `operator_dismissal` сохраняются автор, время, основание и исходные состояния.

- PaymentAttempt остаётся `succeeded`, Fiscalization — `failed`.
- Sale не переводится в `completed` или `cancelled`; суммы и исторические даты не меняются.
- Inventory не меняется, дополнительные движения не создаются.
- Запись исключается из возобновляемых продаж и фильтра активных ошибок.
- История «Все» и просмотр по ID сохраняются с надписью «Операция неактуальна» и
  явным уточнением «Оплата подтверждена, чек не сформирован».
- Retry блокируется на сервере, worker не принимает такое задание; кнопка повторной
  фискализации не показывается. Внешние команды AQSI не отправляются.

Сервис `CheckoutService.dismiss_failed_fiscalization` допускает только окончательно
неуспешную фискализацию без активного задания. Повторная отметка идемпотентна.
Это ограниченная служебная операция без нового общего API или кнопки массового скрытия.
Отметка не закрывает фискальную обязанность и сама по себе не меняет финансовую отчётность.

Проверки: сохранение оплаты/склада/сумм/дат, история и аудит, идемпотентность,
запрет отметки активной операции, отсутствие provider-вызовов и кнопки retry.
Полный набор: 662 серверных теста и 71 интерфейсный тест прошли.
